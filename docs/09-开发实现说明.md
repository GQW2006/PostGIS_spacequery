## 1. 本次做了什么

在一套已就绪的数据资产（PostGIS 3.6 + pgRouting 4.0 + GeoServer）之上，构建了一个 B/S 架构的 WebGIS：

- 后端 Flask 新增 **13 个接口**（任务书要求的 10 个 + 3 个辅助接口：设施总量、区县面、市界），自动生成 OpenAPI 文档；
- 离线脚本预计算 **2SFCA 可达性**、区县人口、设施最近距离等重计算表；
- 前端 Vue3 + Mapbox GL 重构为**三栏 GIS 工作台**：顶栏搜索、左面板图层/分析、地图、右侧详情抽屉、底部状态栏；
- 实现了视口联动（`moveend` + 300ms 防抖）、点聚合、点击分流、六种 UI 状态。

**没有删除任何文件。** 原有 `/api/cities`、`/api/areas`、`/api/areas/point` 三个接口完整保留。

## 4. 后端模块拆解

后端沿用原有 `app/` 目录风格，只做**加法**。分层原则：

```
resources（HTTP 层，只做参数接收与返回）
    ↓
services（业务与 SQL，抛 ValueError / RuntimeError）
    ↓
utils（GeoJSON 组装、异常转换）
schemas（marshmallow 参数与响应结构）
```

### 4.1 模块一：通用响应与异常

**新增** `app/utils/geojson.py`

- `feature(properties, geometry_text, fid)`：把数据库 `ST_AsGeoJSON` 文本转成标准 Feature；
- `feature_collection(features, truncated, **extra_meta)`：统一 `{type, features, meta}`。

**为什么单独抽出来**：设施、区县、分析三类接口都要返回同一种结构，集中一处可保证格式绝对一致，也让资源层只剩一行 `return feature_collection(...)`。

**新增** `app/utils/errors.py`

```python
def api_errors(fn):
    @wraps(fn)
    def wrapper(*args, **kwargs):
        try:
            return fn(*args, **kwargs)
        except ValueError as e:
            abort(400, description=str(e))     # 参数类错误 → 400
        except RuntimeError as e:
            abort(503, description=str(e))     # 依赖未就绪 → 503
    return wrapper
```

业务层只抛 Python 异常，HTTP 状态码的转换集中在一个装饰器里，避免每个视图都写 `try/except`。这是"异常分层"的常见做法。

### 4.2 模块二：设施查询

**新增** `app/services/facility_queries.py`（核心）

| 函数 | 接口 | 关键 SQL |
| --- | --- | --- |
| `query_facilities` | `GET /api/facilities` | `ST_Intersects(geom, ST_MakeEnvelope(...))` |
| `get_facility` | `GET /api/facilities/{id}` | `LEFT JOIN chengdu_districts` 带出区县 |
| `query_nearby` | `GET /api/facilities/nearby` | `ST_DWithin(geom::geography, 点::geography, r)` |
| `category_counts` | `GET /api/facilities/stats` | `GROUP BY category` |
| `query_districts` | `GET /api/districts` | 20 个区县 |
| `query_district_geojson` | `GET /api/districts/geojson` | 简化后的区县面 |
| `query_boundary_geojson` | `GET /api/boundary` | 市域轮廓 |

**三个值得学习的设计点**

1. **bbox 双重校验**：先 `geom && envelope`（走 GiST 索引）再 `ST_Intersects`（精确判断）。`&&` 只是外接矩形相交，必须再用精确函数过滤。
2. **截断而不是全量**：`LIMIT :limit + 1`，多取一条判断是否超限，然后切片并置 `meta.truncated = true`。这样只需一次查询，也不用 `COUNT(*)`。
3. **确定性排序**：`ORDER BY poi_id`。验收要求"同一请求连续 3 次结果 ID 集合一致"，没有稳定排序时数据库可能返回不同顺序。

**距离为什么用 geography**：`geom::geography` 后 `ST_Distance` 单位是米；直接对 4326 几何算距离得到的是"度"，成都纬度下 1 度约 96 km，误差不可接受。

**新增** `app/schemas/facility.py`、`app/resources/facility.py`

- Schema 只声明参数类型与文档描述，具体业务校验（bbox 格式、类型白名单）放在 service，便于单元测试；
- 响应统一用 `FeatureCollectionSchema`。

**修改** `app/schemas/geo.py`

给 `FeatureSchema` 增加 `id`，给 `FeatureCollectionSchema` 增加 `meta`、`stats`。
**原因**：marshmallow 序列化时**只输出已声明字段**，不声明的话 `meta.count`、`stats.coverage_pct` 会被静默丢弃——这是本次开发最容易踩的坑之一。

**修改** `app/resources/geo.py`

新增 `/api/districts`、`/api/districts/geojson`、`/api/boundary` 三个接口。区县面在前端需要用于点击识别与高亮，走自己的 API 比依赖 GeoServer 更稳定。

### 4.3 模块三：区县统计与最近设施

**新增** `app/services/analysis_queries.py` 中的两个函数。

`nearest_facility`：

```sql
SELECT name, district, adcode,
       ST_Distance(geom::geography, 点::geography) AS distance_m
FROM chengdu_poi
WHERE category = :type
ORDER BY geom <-> 点          -- KNN 索引排序，只算 1 条
LIMIT 1
```

`<->` 是 PostGIS 的 KNN 距离运算符，能走 GiST 索引；如果写成 `ORDER BY ST_Distance(...)` 会对 3036 行全部计算函数，虽然数据量小，但这是应养成的习惯。

`district_stats`：

```sql
FROM chengdu_districts d
LEFT JOIN district_pop dp ON dp.adcode = d.adcode
LEFT JOIN chengdu_poi p ON p.adcode = d.adcode AND p.category = :type
LEFT JOIN facility_nearest fn ON fn.poi_id = p.poi_id
GROUP BY d.adcode, d.name, dp.pop2020
```

必须是 `LEFT JOIN`：某个区县没有该类设施时 `COUNT(p.poi_id)` 返回 0 而不是整行消失。验收项"无设施区县不能消失"考的就是这一点。

### 4.4 模块四：2SFCA 预计算（重点）

**新增** `backend/scripts/build_analysis.py`

算法严格按任务书 §5：

```
R_j = S_j / Σ P_i   （S_j = 1，i 为 d_ij ≤ d0 的格网）
A_i = Σ R_j         （j 为 d_ij ≤ d0 的设施）
```

对应 SQL 两步：

```sql
-- 第一步
CREATE TABLE accessibility_rj AS
SELECT f.category, f.poi_id, 1.0 / NULLIF(SUM(g.pop), 0) AS r_j
FROM facility_grid_pairs f JOIN pop_grid_100m g USING (cell_id)
GROUP BY f.category, f.poi_id
HAVING SUM(g.pop) > 0;

-- 第二步
CREATE TABLE accessibility_2sfca AS
SELECT f.category, f.cell_id, SUM(r.r_j)::double precision AS a_i
FROM facility_grid_pairs f
JOIN accessibility_rj r USING (category, poi_id)
GROUP BY f.category, f.cell_id;
```

**为什么先建邻接表**：如果两步各自做一次 `ST_DWithin` 空间连接，等于把最贵的计算做两遍。先物化 `facility_grid_pairs`（114 万行），之后两步都只是普通哈希聚合，各 0.4–2.2 秒。

**稀疏存储与 0 值**：`accessibility_2sfca` 只存 A_i > 0 的格网。半径内没有设施的格网不入表，聚合时用 `COALESCE(s.a_i, 0)` 得到 0。这样既省空间，又满足"0 不能是 NULL"。

**区县聚合**：

```sql
SUM(pgd.pop * COALESCE(s.a_i, 0)) / NULLIF(SUM(pgd.pop), 0)
```

人口加权平均。分母用 `NULLIF` 防止空区县除零，外层再 `COALESCE(..., 0)` 兜底。

**分级用分位数而不是固定阈值**：2SFCA 值是无量纲的（本次结果量级约 1e-4），固定阈值没有意义。用 `percentile_cont(0.25/0.5/0.75)` 对 20 个区县计算阈值，再 `UPDATE ... CASE WHEN value > p75 THEN '优'`。

### 4.5 模块五：覆盖分析、等时圈、导出

**覆盖分析**（`coverage`）：

- 覆盖人口：从设施出发反查半径内格网，再对去重后的格网求和。**不要**从 90 万格网出发对每个格网做 `EXISTS`，那是 9 亿次判断；
- 缓冲区面：`ST_Union(ST_Buffer(geom::geography, r)::geometry)` 溶解成单个多边形，避免把 1000 多个圆传给前端；
- 结果用字典缓存 `(type, radius, district)`，首次 1.9 秒，二次 7 毫秒。

**等时圈**（`isochrone`）：

1. `<->` 找最近路由顶点，超过 200 米直接报"不在可达路网内"；
2. `pgr_drivingDistance(edges_sql, start_vid, seconds, false)`，`cost` 列本身就是步行秒数，所以 `minutes × 60` 直接传；
3. 可达顶点 `ST_ConcaveHull(..., 0.8)` 生成凹包，失败时回退凸包；
4. 用包络面统计面积（`::geography` 后除以 1e6 得 km²）与覆盖人口。

**导出**（`export`）：

- CSV 用 `utf-8-sig` 编码，Excel 打开中文不乱码；
- GeoJSON 直接把区县面与统计结果按 `adcode` 合并；
- 通过 `Content-Disposition: attachment` 触发浏览器下载。

### 4.6 模块六：应用工厂

**修改** `app/__init__.py`

- 注册三个 Blueprint：`geo`、`facility`、`analysis`；
- 统一错误结构：

```python
@app.errorhandler(HTTPException)
def handle_http_exception(e):
    desc = e.description
    if isinstance(desc, dict):   # flask-smorest 的参数校验错误
        return jsonify({"message": "参数校验失败", "details": desc}), e.code

```

## 5. 前端模块拆解

### 5.1 分层与数据流

```
组件（展示/交互）
   ↓ 读
Pinia store（layer / filter / ui）
   ↓ 调
api/*.js（axios 实例）→ /api → Flask → PostGIS
   ↑
composables（跨组件复用逻辑：视口刷新、分析请求）
```

组件的职责边界：

| 层 | 负责 | 不负责 |
| --- | --- | --- |
| 组件 | 渲染、事件 | 不拼 SQL、不直接 fetch |
| store | 共享状态 | 不发请求（filter store 的统计缓存除外） |
| api | 接口封装 | 不处理 UI 状态 |
| composable | 组合流程（请求 + 写 store） | 不渲染 |

### 5.2 模块七：状态层（新增文件）

**`src/stores/layer.js`**

- `base`：区县界/市界显隐；
- `facilities`：三类设施显隐 + 数量（数量来自 `/api/facilities/stats`，不是 mock）；
- `analysis`：服务区/可达性/等时圈显隐；
- `coverageData / accessibilityData / isochroneData`：用 `shallowRef` 存 GeoJSON（大对象不需要深层响应式）；
- `legendItems`：计算属性，图例由图层状态推导——**关闭图层图例自动消失**，不需要手动同步。

**`src/stores/filter.js`**

- `activeType`、`radius`、`district`、`keyword`、`tab`；
- `stats`：loading / loaded / error / count / truncated，六个状态里的加载、空、错误全靠它；
- `loadDistrictStats(type)` 带 `Map` 缓存，避免反复请求。

**`src/stores/ui.js`**（任务书只列了两个 store，这里拆出第三个）

抽屉、坐标、缩放、底图、网络、登录态、飞行定位指令。理由是这些与"筛选"无关，塞进 filter 会让它迅速膨胀。**状态按领域拆分，而不是按页面拆分**，是 Pinia 的常规实践。

### 5.3 模块八：地图工作台（`MapView.vue` 重写）

这是全项目最复杂的组件，按职责分成四块：

**(1) 图层安装 `installLayers()`**

- 图标：Mapbox 没有现成 sprite，用 canvas 画圆/旋转 45° 的方块，白色描边，`addImage` 注册；
- 设施源开启 `cluster`，`clusterMaxZoom: 11`，低缩放级别自动聚合；
- 三类设施用**三个 symbol 图层 + filter 表达式**区分，而不是三个数据源；
- 分析图层（coverage / accessibility / isochrone）各自独立 source，数据为空时也先建好，后续只需 `setData`。

**(2) 视口联动**

```js
m.on('moveend', () => { ...; refresh() })   // refresh = debounce(loadFacilities, 300)
```

只在 `moveend` 触发（不是 `move`），再叠加 300ms 防抖，满足"连续拖动 10 次请求 ≤ 2 次"。

**(3) 点击分流**

按优先级判断：

1. 命中设施图层 → 打开设施抽屉；
2. 命中聚合气泡 → `getClusterExpansionZoom` 放大；
3. 命中区县面 → 打开区县抽屉；
4. 都没有 → 用客户端射线法判断所属区县，并请求 500m 内设施，一次点击同时给出"归属 + 周边"。

**(4) 底图切换**

`setStyle` 会清空所有图层，因此必须在 `style.load` 后重新 `installLayers`，再用 `lastFacilityFC` 恢复数据。这是 Mapbox 开发中的固定套路。

**错误处理**：请求失败只设置 `filter.stats.error`，**不调用 `setData([])`**，所以旧数据仍留在地图上，符合"停掉后端保留旧数据"的要求。

## 11. 补充迭代：接入 GeoServer 发布图层

### 11.1 为什么改成 WMS

第一版把区县/市界做成前端 GeoJSON 面，路网与人口栅格没有接。第二轮改为：

| 图层 | 渲染方式 | 说明 |
| --- | --- | --- |
| `chengdu:chengdu_districts` | GeoServer WMS | 区县界，默认显示 |
| `chengdu:chengdu_boundary` | GeoServer WMS | 市界，默认显示 |
| `chengdu:chengdu_roads` | GeoServer WMS | 路网（20 万条），默认关闭 |
| `chengdu:population` | GeoServer WMS | 人口栅格，默认关闭 |
| `chengdu:chengdu_poi` | Flask API → GeoJSON | 需要点击、聚合、按类型/区县筛选，WMS 栅格做不到 |

**结论**：需要交互的图层走矢量 API，只做视觉展示的大图层走 WMS。这也是"双地理服务"分工的落地。

### 11.2 新增文件

`PostGIS/src/api/geoserver.js`

```js
export function wmsTileUrl(layerName, { format = 'image/png', styles = '' } = {}) {
  const params = new URLSearchParams({
    service: 'WMS', version: '1.1.1', request: 'GetMap',
    layers: layerName, styles, format, transparent: 'true',
    srs: 'EPSG:3857', width: '256', height: '256',
    bbox: '{bbox-epsg-3857}',
  })
  return `/geoserver/wms?${params.toString()
    .replace('%7Bbbox-epsg-3857%7D', '{bbox-epsg-3857}')}`
}
```

三个关键点：

1. **`srs=EPSG:3857`**：WMS 1.3.0 + 4326 的轴序是"纬度在前"，按经度在前拼 bbox 会渲染空白；3857 轴序固定 x,y，且与 Mapbox 瓦片坐标系一致；
2. **`{bbox-epsg-3857}` 占位符**：Mapbox 会为每张瓦片替换成实际范围，所以一个 URL 就能覆盖所有缩放级别；
3. **占位符还原**：`URLSearchParams` 会把 `{}` 编码成 `%7B%7D`，必须替换回来，否则 Mapbox 不认识。

`wmsSource(layerName)` 返回 Mapbox raster source 配置（`tiles` + `tileSize: 256`），MapView 直接 `addSource`。

### 11.4 点击识别怎么改

WMS 是栅格图片，`map.queryRenderedFeatures` 拿不到区县属性。因此点击流程改为：

```
点击 → 命中设施点？（矢量图层）→ 设施抽屉
     → 命中聚合气泡？        → 放大
     → 其余：射线法判断点落在哪个区县面
         在区内 → 区县抽屉（统计 + 周边）
         在区外 → 任意点抽屉（归属 + 周边）
```

区县 GeoJSON 仍然请求（`/api/districts/geojson`），但**只用于计算与高亮**，不再作为可视化图层，避免与 WMS 重复渲染。

### 11.5 顺手修掉的两个运行时错误

| 报错 | 原因 | 修复 |
| --- | --- | --- |
| `api.mapbox.com/fonts/.../DIN%20Offline%20Regular... 404` | 聚合数字图层写死了底图不存在的字体 | 移除 `text-font`，使用样式默认字体 |
| `failed to invert matrix` + `Invalid LngLat object: (NaN, NaN)` | 地图容器在布局完成前尺寸为 0，`fitBounds` 算出 NaN 变换 | `.map` 改 `position:absolute; inset:0`；`requestAnimationFrame` 后先 `resize()` 再 `fitBounds`；`getBounds/flyTo` 增加有限值校验；面板收起后延迟 `resize()` |
| `Uncaught (in promise) TypeError: t is not a function` | `GeoJSONSource.getClusterExpansionZoom(clusterId)` 在该版本是**回调式** API，直接 `await` 会得到 source 本身，内部调用 `callback(...)` 时 callback 为 undefined | 手动包一层 Promise：`new Promise((res, rej) => src.getClusterExpansionZoom(id, (e, z) => e ? rej(e) : res(z)))` |
| 等时圈 `400 不在可达路网内` | 两次修复：① 只吸附"最近路由顶点"时误差大 → 改吸附最近道路；② 仍有端点误差与 bbox 选边问题 | **最终方案**：`ST_DWithin` 粗筛 + `ST_Distance(geography)` 精排选边；不吸附端点，按 `frac` 把预算拆成两段分别从 source/target 扩散；凹包点集包含点击位置；节点数 < 10 抛"连通性不足" |

> 这类错误的表现往往是一串连锁报错（矩阵 → 反投影 → 鼠标事件），真正根因只有"容器尺寸为 0"这一个，定位时要从第一条报错看起。

| 提示 | 说明 |
| --- | --- |
