# 1. 症状

打开"人口栅格"图层后，整个市域是一块纯黑，看不出人口分布，观感很差。

---

# 2. 根因（三条，均有实测依据）

## 2.1 GeoServer 用了自带灰度样式

图层 `chengdu:population` 创建时自动绑定了 GeoServer 内置的 `raster` 样式——**从最小值到最大值线性映射灰度**。

而这张栅格的实际分布极度右偏：

| 统计量 | 值（人 / 100m 像元） |
| --- | --- |
| p50 | **0** |
| p70 | 1.1 |
| p80 | 4.2 |
| p90 | **15.4** |
| p95 | 37.7 |
| p99 | 130.5 |
| max | 2,818.7 |

一半像元是 0，90% 的值不超过 15.4，而映射区间是 0–2818。
**线性灰度下，几乎所有像元都落在最暗端 → 整幅黑。**

## 2.2 nodata 未特殊处理

像元值 `-1` 表示市域外，同样被当作数据参与灰度映射。

## 2.3 图例只给了一个色块

`layer.js:61`：

```js
items.push({ key: 'wms-population', label: '人口栅格', color: '#E8743B', shape: 'square' })
```

一个橙色方块。**五档配色配一个色块图例，等于没有图例。**

## 2.4 放大后出现"麻点"

像元只有 100m。放大到 0.35° 经度占 760px 时，一个像元约 **2.3 像素**，
相邻像元值差异大（城区高、公园/道路/水面为 0 并透明），画面呈散点状，
读起来是噪声而不是密度场。

# 3. 已完成的修复（已落地 GeoServer，实测通过）

## 3.1 做了什么

1. 按 `docs/03-UI设计规范.md` §4.1 定义的人口色带，创建 SLD 样式
   **`chengdu:population_density`**；
2. 将其设为 `chengdu:population` 的**默认样式**。

样式文件：[`data_pipeline/geoserver/population_density.sld`](../data_pipeline/geoserver/population_density.sld)

## 3.2 分级依据

不按等距均分，按实测分布定档。像元 100m×100m = 0.01 km²，
故 `人/像元 × 100 = 人/km²`：

| 像元值 | 密度（人/km²） | 含义 | 颜色 | 透明度 |
| --- | --- | --- | --- | --- |
| -1 | — | 市域外 | — | 0 |
| 0 | 0 | 无人 | — | 0 |
| 1–5 | 100–500 | 极稀疏 | `#EEF5FB` | 0.55 |
| 5–20 | 500–2,000 | 稀疏 | `#D6E4F0` | 0.80 |
| 20–60 | 2,000–6,000 | 低密 | `#7BA7D9` | 0.85 |
| 60–150 | 6,000–15,000 | 中密 | `#F5D76E` | 0.85 |
| 150–400 | 15,000–40,000 | 高密 | `#E8743B` | 0.88 |
| >400 | >40,000 | 极高 | `#9C1650` | 0.92 |

**关键设计**：0 值与市域外**完全透明**，让底图、路网、设施点透出来——
人口图层是叠加层，不是底色层。

## 3.3 效果

- 修复前：整幅纯黑（WMS 渲染 51 KB，几乎全黑像素）
- 修复后：城郊浅蓝、城区黄→橙→绛紫的密度场；全域视图可读

## 3.4 回滚（如需）

```bash
curl -u admin:geoserver -X PUT \
  -H "Content-Type: application/json" \
  -d '{"layer":{"defaultStyle":{"name":"raster"}}}' \
  http://localhost:8080/geoserver/rest/layers/chengdu:population
```

> 注意：用 PowerShell 写 JSON 文件时不要带 BOM，否则 GeoServer 返回 500。
> 用 `python -c "open(...,'w',encoding='utf-8')"` 或 `Set-Content -Encoding utf8NoBOM`。

# 4. 待改项（执行 Agent 从这里开始）

## C1　图例改为色带（必做）

**问题**：五档配色配一个橙色方块，用户无法把颜色翻译成数字。

**改 `src/stores/layer.js:60-62`**，把单项改为色带项：

```js
if (geoserver.population) {
  items.push({
    key: 'wms-population',
    label: '人口密度',
    type: 'ramp',
    unit: '人/km²',
    stops: [
      { label: '100–500',    color: '#EEF5FB' },
      { label: '500–2千',    color: '#D6E4F0' },
      { label: '2千–6千',    color: '#7BA7D9' },
      { label: '6千–1.5万',  color: '#F5D76E' },
      { label: '1.5万–4万',  color: '#E8743B' },
      { label: '> 4万',      color: '#9C1650' },
    ],
  })
}
```

**改 `src/components/Legend.vue`**，在 `.item` 循环内增加 ramp 分支：

- `item.type === 'ramp'` 时渲染为一组行：色块（`12×10px`，无圆角）+ 数值区间文字（`--fs-caption`）；
- 顶部加一行 `item.label` + `item.unit` 作为小标题；
- 其余形态（circle / square / ring / line）保持不变。

**验收**：开启人口图层后，图例显示 6 档色带与"人/km²"单位，颜色与地图一一对应。

---

## C2　加缩放策略（必做）

**问题**：100m 像元在放大约 2–3 像素时呈散点噪声。

**改 `src/components/MapView.vue:102-116`**：给 WMS 图层加缩放边界。

```js
const wmsConfig = [
  ['wms-population', WMS_LAYERS.population, 0.72, { maxzoom: 13 }],
  ['wms-districts',  WMS_LAYERS.districts,  0.9,  {}],
  ['wms-boundary',   WMS_LAYERS.boundary,   1,    {}],
  ['wms-roads',      WMS_LAYERS.roads,      0.9,  {}],
]
```

`addLayer` 时把缩放参数平铺到图层配置（`minzoom` / `maxzoom` 属于**图层**属性，不是 paint）：

```js
m.addLayer({
  id,
  type: 'raster',
  source: id,
  ...zoomBounds,                       // { minzoom, maxzoom }
  paint: { 'raster-opacity': opacity },
})
```

**效果**：Z ≤ 13 显示密度场；Z > 13 自动隐去，避免散点噪声，此时用户看的是设施点与分析面，信息不丢。

**验收**：Z8 显示密度场；Z14 时人口图层不再渲染，且图层开关状态保持正确（重新缩回 Z≤13 应恢复显示）。

---

## C3　透明度微调（建议）

`MapView.vue:103` 当前为 `0.6`。改成 `0.72`。

原因：色带的最低两档已经很淡（0.55 / 0.80 自带 alpha），再叠加整体 0.6 会让城郊几乎看不见；
提高到 0.72 可以兼顾"看得见分布"和"不压住底图路名"。

**验收**：城区密集区颜色可辨，底图道路名在浅色区域仍可读。

---

## C4　（可选，需确认）500m 聚合显示栅格

如果希望在高缩放级别也能看到人口，需要为**显示**单独做一张粗粒度栅格，而不是放开 `maxzoom`。

思路：把 100m 重采样为 500m，按 5×5 求均值再 ×25（保持"人/格"语义），
阈值同比 ×25（1→25、5→125、20→500、60→1500、150→3750、400→10000），配第二套 SLD。

**这一步涉及新建表和发布图层，不属于前端改动。是否要做请先确认**——
若只做 C1–C3，高缩放级别没有人口底图，已能满足"看得清、看得懂"。
