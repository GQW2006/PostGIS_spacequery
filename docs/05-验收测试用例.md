# 〇、术语与判定

| 判定 | 含义 |
| --- | --- |
| **PASS** | 实测值落在预期区间内 |
| **FAIL** | 超出区间，必须修代码或修数据，**不允许修改预期值** |
| **BLOCK** | 前置条件不满足，无法执行（要记录原因） |

判定优先级：`PASS > FAIL > BLOCK`。一个用例只要 FAIL 就不能进入下一迭代。

```sql
SELECT category, count(*) FROM chengdu_poi GROUP BY 1 ORDER BY 1;
```

**预期**：小学 1,085 / 中学 771 / 菜市场 1,180

# 三、A 组：算法层用例（2SFCA 与对照指标）

## T-A01　最近设施距离 —— 与基准值一致

**步骤**：

```sql
SELECT name,
       round(ST_Distance(geom::geography,
             ST_SetSRID(ST_MakePoint(104.0658,30.6571),4326)::geography)::numeric, 1) AS d
FROM chengdu_poi WHERE category='小学'
ORDER BY geom::geography <-> ST_SetSRID(ST_MakePoint(104.0658,30.6571),4326)::geography
LIMIT 1;
```

**预期**：`成师附小`，**419.8 m**（容差 ±0.5 m）
**判定**：名称不符 → FAIL；距离偏差 > 0.5m → FAIL

> **双重校验**：接口返回的必须是同一个值；
> 另需与高德地图实测误差 < 20%（数据准确性，非链路准确性）。

---

## T-A02　半径内设施计数

```sql
SELECT category, count(*) FROM chengdu_poi
WHERE ST_DWithin(geom::geography,
      ST_SetSRID(ST_MakePoint(104.0658,30.6571),4326)::geography, 1000)
GROUP BY 1;
```

**预期**：小学 **9** / 中学 **5** / 菜市场 **2**
**判定**：任一不符 → FAIL

> 这条同时验证了 `ST_DWithin` 走索引时的正确性。如果数字偏大，
> 通常是误用了度单位（`geography` 换成了 `geometry`）。

---

## T-A03　区县统计一致性

```sql
SELECT d.adcode, d.name, count(p.poi_id) AS schools
FROM chengdu_districts d
LEFT JOIN chengdu_poi p ON p.category='小学' AND ST_Contains(d.geom, p.geom)
WHERE d.adcode='510107' GROUP BY 1,2;
```

**预期**：`510107 武侯区 88`
**判定**：与接口返回的 `district-stats` 中武侯区数值完全一致，否则 FAIL

> 注意用 `LEFT JOIN`：没有设施的区县要返回 0 行，不能凭空消失。

---

## T-A04　2SFCA 小样本手算（**最关键的一条**）

> 2SFCA 最容易在第一步的分母范围上写错，且错得很隐蔽。
> 必须挑一个小样本手算，与 SQL 结果对拍。

**样本选择**：取 `成师附小`（天府广场最近小学）作为设施 `j`，
取其 1000m 内的所有人口格网作为 `i` 集合。

**手算步骤**

```
1. 取该学校坐标 (lon_j, lat_j)
2. 找出半径 1000m 内所有人口格网，读其人口值 P_i
3. 求和：SOMPOP = Σ P_i
4. 供需比：R_j = S_j / SOMPOP，其中 S_j = 1
```

**SQL 对拍**

```sql
WITH j AS (
  SELECT poi_id, geom FROM chengdu_poi
  WHERE category='小学' ORDER BY 1 LIMIT 1
), cells AS (
  SELECT (g).geom AS cg, (g).val AS pop
  FROM chengdu_pop_100m, ST_PixelAsCentroids(rast, 1, false) g
)
SELECT j.poi_id,
       count(*) FILTER (WHERE ST_DWithin(c.cg::geography, j.geom::geography, 1000)) AS n_cells,
       sum(c.pop) FILTER (WHERE ST_DWithin(c.cg::geography, j.geom::geography, 1000)) AS sompop,
       1.0 / NULLIF(sum(c.pop) FILTER (WHERE ST_DWithin(c.cg::geography, j.geom::geography, 1000)),0) AS r_j
FROM j CROSS JOIN cells c
GROUP BY j.poi_id;
```

**预期**：`n_cells` 约 **300–320**（π×10²），`sompop` 在 1–20 万量级，
`r_j` 在 1e-5 量级
**判定**：手算与 SQL 相对误差 < 1% → PASS

> 若 `n_cells` 明显偏离 300 左右，说明半径算错了（大概率是度 vs 米）。

---

## T-A05　2SFCA 第二步对拍

**步骤**：取一个具体格网 `i`，算出 `A_i = Σ R_j`（1000m 内所有小学），
手工累加与 SQL 结果对比。

**预期**：相对误差 < 1%
**判定**：不一致 → FAIL（通常是第一步的 `R_j` 缓存错了，或半径不一致）

---

## T-A06　边界情况：半径内无设施

**步骤**：取一个远郊格网（例如西部山区），计算 `A_i`。

**预期**：`A_i = 0`（**不是 NULL，不是报错**）
**判定**：返回 NULL 或抛异常 → FAIL

> 这条经常被忽略。山区大量格网半径内没有学校，
> 如果实现里用了 `INNER JOIN`，这些格网会整片消失，热力图会出现空洞。

---

## T-A07　分级阈值渲染

**步骤**：检查分级接口返回的 `level` 与 `value` 的对应关系。

**预期**：同一 `value` 在全库中只能对应唯一 `level`；四档数量分布接近 25/25/25/25
**判定**：出现同一值两个等级 → FAIL（阈值边界处理有误，`>` 和 `>=` 混用了）

---

# 四、R 组：路网与等时圈用例（pgRouting）

## 前置：拓扑清洗交付契约

> 拓扑清洗由你完成。为了让后续调用能对接，请交付**表 `chengdu_roads_routing`**，
> 结构与下图一致。没有这张表，R 组全部 BLOCK。

```sql
CREATE TABLE chengdu_roads_routing (
    id           bigint PRIMARY KEY,        -- 整数边 ID（Overture 的 uuid 需映射）
    overture_id  varchar(64),               -- 保留原始 ID 便于回溯
    source       bigint,                    -- 起点顶点，pgr_createTopology 生成
    target       bigint,                    -- 终点顶点
    length_m     double precision,          -- 长度（米）
    cost         double precision,          -- 正向通行时间（秒）
    reverse_cost double precision,          -- 反向通行时间（秒），单行/禁行 = -1
    road_class   varchar(40),               -- 保留等级，便于按等级过滤
    geom         geometry(LineString, 4326)
);
CREATE INDEX ON chengdu_roads_routing USING GIST (geom);
CREATE INDEX ON chengdu_roads_routing (source);
CREATE INDEX ON chengdu_roads_routing (target);
```

**成本口径（务必统一，否则等时圈数值无意义）**

| 模式 | `cost` 定义 | 说明 |
| --- | --- | --- |
| 步行 | `length_m / 1.2` | 1.2 m/s ≈ 4.32 km/h，常用值 |
| 驾车 | `length_m / (v_kmh / 3.6)` | `v_kmh` 按等级取默认值 |

**禁行处理**：`motorway` / `trunk` 对步行应设 `cost = -1`（pgRouting 视为不可通行）。

**容差建议**：`pgr_createTopology` 的容差参数取 **0.00005 度**（成都纬度约 5.5 m）。
太大（0.0001 以上）会把平行车道合并成一条，太小会导致路口不连通。

---

## T-R01　路网连通性（拓扑清洗的验收）

```sql
CREATE EXTENSION IF NOT EXISTS pgrouting;

SELECT count(DISTINCT component) AS n_components,
       (SELECT count(*) FROM pgr_connectedComponents(
            'SELECT id, source, target, cost, reverse_cost FROM chengdu_roads_routing'
        ) WHERE component = (
            SELECT component FROM (
                SELECT component, count(*) c FROM pgr_connectedComponents(
                    'SELECT id, source, target, cost, reverse_cost FROM chengdu_roads_routing'
                ) GROUP BY component ORDER BY c DESC LIMIT 1
            ) t))                AS largest_size,
       (SELECT count(*) FROM chengdu_roads_routing) AS total_edges
FROM pgr_connectedComponents(
    'SELECT id, source, target, cost, reverse_cost FROM chengdu_roads_routing'
);
```

**预期**：`largest_size / total_edges` **> 0.90**
**判定**：< 0.90 → FAIL（大量路段未连通，容差或打断规则有问题）

> 现实里很难到 1.0（远郊路网天然离散），但主城连通分量应显著占优。
> 如果只有 0.3，说明 `source/target` 基本没建对。

---

## T-R02　等时圈面积单调性

**步骤**：以天府广场为起点，分别算 5 / 10 / 15 分钟步行圈。

```sql
-- 5 分钟 = 300 秒，步行
SELECT count(*) FROM pgr_drivingDistance(
  'SELECT id, source, target, cost, reverse_cost FROM chengdu_roads_routing',
  (SELECT id FROM chengdu_roads_routing_vertices_pgr
     ORDER BY the_geom <-> ST_SetSRID(ST_MakePoint(104.0658,30.6571),4326) LIMIT 1),
  300, false
);
```

**预期**：节点数 5min < 10min < 15min，且大致呈 1 : 3.5 : 7 的超线性增长
**判定**：任一不单调 → FAIL

---

## T-R03　等时圈包含性

**步骤**：在 10 分钟圈内随机取 20 个路网节点，用
`pgr_dijkstra` 算其到起点的实际耗时。

**预期**：全部 ≤ 600 秒（容差 +1%）
**判定**：出现 > 600 秒的节点 → FAIL（alphaShape 或凹包参数过松）

---

## T-R04　等时圈 vs 直线缓冲区（**结论性对拍**）

**步骤**：同一起点、同一半径（步行 1000m），分别算：

- 直线缓冲区面积：`ST_Area(ST_Buffer(起点::geography, 1000))`
- 等时圈面积

**预期**：**等时圈面积 / 缓冲区面积 落在 0.30 – 0.70**
**判定**：> 0.90 → FAIL（大概率退化成圆形，说明路网没真正参与计算）

> 这个比值就是"绕路效应"的量化，也是作品集里最直观的一张对比图。
> 如果接近 1，说明你实际算的还是直线距离。

---

## T-R05　孤立起点

**步骤**：取一个不在最大连通分量里的节点作为起点。

**预期**：接口返回明确的业务错误（如"该位置不在可达路网内"），
**不是** 500，**也不是**空数组装成功。
**判定**：500 或静默返回空 → FAIL

# 九、执行顺序与出口条件

```
第 1 轮（数据 + 算法）
  T-D01 ~ T-D05  →  T-A01 ~ T-A07
  出口：全部 PASS 才能开始写接口

第 2 轮（接口 + 性能）
  T-I01 ~ T-I07  →  T-P01 ~ T-P05
  出口：接口全部 PASS，性能全部达标

第 3 轮（路网，取决于清洗进度）
  T-R06 → T-R01 → T-R02 → T-R03 → T-R04 → T-R05

  T-F01 ~ T-F07  →  T-G01 ~ T-G03
  出口：全部 PASS 可交付
```
